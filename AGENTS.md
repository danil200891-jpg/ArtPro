# ArtProduction: правила обращения в текстах

Предпочтение пользователя, закреплённое 2026-11-01 (источник: `D:\CODEX\WEB\AGENTS.md`).

Инструкции общие для Codex (`AGENTS.md`) и Claude (`CLAUDE.md`). Оба файла должны содержать одинаковые правила: при изменении одного файла так же обновлять другой.

Эти правила обязательны при любых изменениях сайта: при написании и правке текстов, добавлении отзывов, изменении интерфейса с текстовыми подписями, метаданных (title, description, Open Graph) и при переводах на все языковые версии (ES, RU, UA, EN). Перед завершением правки проверять, что новые и затронутые тексты во всех языках им соответствуют.

- Во всех текстах использовать обращение на «вы», без «ты» и связанных форм единственного числа.
- ArtProduction — компания, а не отдельный специалист. В отзывах и других обращениях к ArtProduction адресат — фирма: «вы помогли», «вы почувствовали», «ваша команда».
- От лица ArtProduction писать «мы», «наша команда», «наша компания», а не «я».
- Соблюдать это правило во всех языковых версиях. При переводе учитывать, что обращение направлено к компании/команде; согласовывать местоимения и глаголы. В ES при обращении к ArtProduction использовать ustedes и соответствующие формы глаголов; в UA — «ви»; в EN — you, а от лица компании — we.
- Сохранять первое лицо автора отзыва («я», «мой продукт»): это голос клиента, а не ArtProduction.

# ArtProduction: порядок работы после изменений сайта

Постоянное правило пользователя, закреплённое 2026-11-03. Действует во всех будущих сессиях Claude и Codex при работе с сайтом ArtProduction.

После каждого изменения сайта:

1. Выполнять проверку сборки (`npm run build`, включает `check:localization`) и проверять все четыре языка: ES, RU, UA, EN.
2. Запускать локальный сервер предварительного просмотра (`npm run dev`), если он ещё не запущен.
3. Всегда предоставлять кликабельную ссылку на актуальную локальную версию сайта для проверки в браузере, например `http://127.0.0.1:5173/`. Указывать фактический адрес и порт запущенного сервера.
4. Убеждаться, что ссылка работает и показывает последние изменения.
5. После проверки обязательно задавать вопрос: «Публикуем обновления на сайте artprobcn.es?»
6. Предлагать два варианта ответа: «Да, опубликовать» и «Нет, продолжить редактирование».
7. Только после явного согласия пользователя выполнять commit и push в GitHub `main`, затем проверять результат публикации (workflow «Deploy ArtProduction to GitHub Pages» и сайт artprobcn.es).
8. Если пользователь не подтвердил публикацию, все изменения остаются локальными: без commit и push.
